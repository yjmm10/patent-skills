# Iteration — 增量润色

当用户在上轮交付的润色稿或原稿上提出**局部修改**时执行；**不**默认重跑 full diagnose。

## 识别迭代意图

- 「把摘要第二句改强一点」
- 「贡献第 3 条和方法章不一致，统一一下」
- 「实验段加上消融表述，但不要动引言」
- 附件/路径指向上轮 `polished_*.md`

## 执行门禁

1. **Read** 用户指定的当前稿（上轮输出优先于原稿）
2. **明确范围**：只改用户点名的章节/段落/图题
3. 若修改涉及**全局术语或数值**：Grep 全文影响范围，一并统一
4. **Read** 相关 chapter-guidelines 节；小改可不跑 full self_check，但至少核对数值一致

## 输出

- 更新后的**完整章节或全文**（用户若只要 diff，则提供 diff + 该段终稿）
- **增量变更摘要**（追加到上轮 Change Log 风格）
- 新文件：`polished_{新时间戳}.md`，**不覆盖**旧稿（除非用户明确要求）

## 禁止

- 不因「顺便」重写未要求章节
- 不撤销用户明确保留的表述

## 对话记录（可选）

若多轮迭代，可在 `outputs/{论文标识}/polish_iteration_log.md` 追加：

```markdown
## {timestamp}
- 用户请求：...
- 修改范围：Abstract ¶2, Contribution 3
- 输出文件：polished_xxx.md
```
